\# Future tooling note: sound catalog generation and package integrity

Need a future design for managing large sound catalogs without manually writing hundreds of Lua path entries. Possible direction: use approved sound folders plus generated or scanned catalog data. Also need a way to make user modifications safer: clear folder boundaries, validation/debug checks, missing-file reporting, and documented “official package” versus “local custom sounds” behavior. This is not a security boundary; users can modify local files. The goal is maintainability, accidental-damage prevention, and easier support.
